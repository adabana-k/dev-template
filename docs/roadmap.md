# Roadmap

## Phase 1 — 初期テンプレートと人間主導
- 共通コマンド、仕様書、環境定義、CI、Issue/PRテンプレートを整備。
- GitHub登録、Codespaces/Codex接続、別端末再開を確認。
- テスト用Issue → 実装 → PR → CI → 人間レビュー → マージを実証。
- AI提案を人間が選択する。利用先プロダクトの目的を記入する。

## Phase 2 — 提案とIssue下書き
- 仕様、コード、未完了Issue、最近のPR、テストと技術的負債から候補を評価。
- Issue下書きを人間が承認し、Codex実装、PR、CI、人間レビューへ進む。
- 定期実行先・認証・予算・通知先を選定する。初期はIssueを自動作成しない。

## Phase 3 — 承認した範囲で自動化
- 重複防止と権限分離を備えたIssue作成 → 実装 → PR → CIを導入。
- 最終マージ、重要変更は引き続き人間が判断する。

## Phase 4 — 利用データ
- 利用データの収集方針と指標を定義し、課題検出と機能提案に反映する。
- 方向性、重要設計、認証、破壊的DB変更、本番削除等を完全自動化しない。
